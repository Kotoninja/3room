# Решения и допущения

Источник требований — [SPEC.md](SPEC.md). Здесь записаны решения о переходе и трактовка неоднозначных формулировок.

- **2026-11-26 — Переход к новой спецификации.** RoomForge используется в документации как рабочее имя из SPEC. Идентификатор npm-пакета `3room` сохраняется до отдельной задачи на переименование. Локальный конструктор одного этажа, смета, IndexedDB и экспорт входят в текущий объём. Сервер публикаций, арендаторы, облако и ML относятся к прежнему плану.
- **Переиспользование кода.** Текущие инструменты SVG/R3F, история и калибровка — основа для перехода. Существующий граф с ID вершин отличается от формата стены с `a`/`b` и собственной высотой. В T02–T04 доменная модель приводится к SPEC §5–6. Производный граф строится из единого плана в T13. Вторую редактируемую модель заводить не требуется.
- **Стек мигрирует по задачам.** Текущая сборка использует React 19, R3F 9, Drei 10, Tailwind и Oxlint. Целевой стек из §3 обязателен. T01 отвечает за совместимость React 18/R3F 8/Drei 9, включая замену API React 19, TypeScript strict, ESLint/Prettier и CI. T05 переносит стили в CSS Modules и строки в словарь. T14–T15 заменяют FloorPlanNet/ONNX чистым TypeScript и удаляют прежнюю зависимость из штатного сценария. Этот документ не разрешает отклонений от §3.
- **Зазоры в распознавании.** В двусмысленном §8.5.10 зазор 0,6–1,3 м при выполнении прочих условий даёт одну объединённую стену с дверным проёмом. Малые зазоры сливаются по шагу 9. Остальные разрывы сохраняются.
- **Форматы.** В интерфейсе ручной импорт растра поддерживает PNG, JPEG и WebP по §8.2. JSON-экспорт проекта включает имя и план с версией 1, подложка сохраняется отдельно в IndexedDB (§13).
- **Приёмка демо.** T22 остаётся условной задачей по §16. Если она сокращается, обязательный E2E с демо из §15 всё равно требует минимальной команды загрузки демо-плана из T02, которую проверяет T24.
- **Порядок работ.** Номера T01–T25 и календарь взяты из §16. Связи в трекере отражают технические предпосылки. Для общей последовательности и правил сокращения используется §16. Старые статусы resolved относятся к прежней версии продукта и не заменяют приёмку T-задач.
