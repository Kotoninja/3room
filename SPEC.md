## 1. Цель и границы

### 1.1 Что это
Веб-приложение (только фронтенд, без сервера), в котором пользователь строит 3D-модель помещения двумя способами:

1. **Из растрового чертежа.** Загрузил PNG/JPG плана → задал масштаб → нажал «Распознать стены» → получил стены в редакторе → поправил руками → смотрит 3D.
2. **С нуля.** Рисует стены, двери, окна и расставляет мебель в 2D-редакторе → одновременно видит 3D.

Прототип-ориентир: проект InWorS (автор Пётр Птушкин): план любого масштаба превращается в 3D, стены рисуются интуитивно, расставляется мебель, считаются затраты. Мы делаем **браузерную, более простую и более доступную** версию с калибровкой масштаба, ручной правкой результата распознавания, сметой и экспортом.

### 1.2 Срок и команда
Сдача **2 декабря 2026**. Команда: 2 человека + ИИ-агенты. Старт разработки 26 ноября. Поэтому: MVP, минимум зависимостей, всё покрыто простыми тестами.

### 1.3 Не-цели (НЕ делать)
- Сервер, база данных, авторизация, облако, совместная работа.
- Нейросети и ML-распознавание.
- Несколько этажей, лестницы, крыши, кривые и дуговые стены.
- Физически точный рендер, текстуры из интернета, PBR-материалы.
- Распознавание текста, размеров, дверей и окон по картинке (кроме простого случая из §8.7).
- Мобильная версия (должна не ломаться, но не оптимизируется).

## 5. Доменная модель

### 5.1 Единицы и системы координат (ВАЖНО)
- Все длины в плане — **метры** (`number`).
- **План (2D):** `x` вправо, `y` **вниз** (как на экране). Угол — `Math.atan2(dy, dx)`, радианы.
- **3D (three.js):** `X = x`, `Z = y`, `Y` — вверх. Точка плана `(x, y)` → `new Vector3(x, 0, y)`.
- Поворот объекта в 3D: `rotation.y = -angleInPlan`.
- Пиксели картинки → метры: `metersPerPixel` (м/пикс), начало координат картинки = точка `(0, 0)` плана, верх-лево.

## 6. Состояние и история

### 6.1 `planStore` (zustand + immer)
Хранит `plan: Plan` и историю `past: Plan[]`, `future: Plan[]` (снимки, лимит 100).

Действия (все возвращают id созданного объекта, где применимо):

```
addWall(a, b, opts?) / updateWall(id, patch) / moveWallEnd(id, 'a'|'b', point) / removeWall(id)
addOpening(wallId, kind, offset) / updateOpening(id, patch) / removeOpening(id)
addFurniture(type, position) / updateFurniture(id, patch) / removeFurniture(id)
replaceAll(plan)               // загрузка проекта, ЧИСТИТ историю
mergeWalls(walls, openings)    // принять результат распознавания — ОДИН шаг истории
undo() / redo() / canUndo / canRedo
beginTransaction() / endTransaction()   // для перетаскивания: один шаг истории на весь drag
```

Правила:
- Каждое изменяющее действие вне транзакции пушит снимок в `past` и чистит `future`.
- Во время `pointermove` при перетаскивании пользуемся транзакцией: снимок один раз в `pointerdown`.
- При удалении стены удаляются её проёмы. При укорачивании стены проёмы, вышедшие за длину, прижимаются (`clamp`) или удаляются, если не помещаются.
- Минимальная длина стены 0.05 м; стены короче не создавать.

### 7.1 Разрезание стен и поиск комнат (`planarGraph.ts`)

`findRooms(walls: Wall[]): Room[]`

1. **Узлы и рёбра.** Для каждой пары стен найти пересечения/касания (в т.ч. конец одной стены лежит на другой с допуском `0.05 м`). Разрезать стены в этих точках. Слить узлы, лежащие ближе `0.05 м`. Результат: граф `nodes[]`, `edges[]` (без дублей).
2. **Полурёбра.** Каждое ребро → 2 направленных полуребра.
3. **Сортировка.** В каждом узле отсортировать исходящие полурёбра по углу.
4. **Обход граней.** Для полуребра `u→v` следующее полуребро — `v→w`, где `w` — сосед `v`, идущий **сразу за обратным ребром** `v→u` в порядке сортировки (поворот в одну и ту же сторону). Идти, пока не вернёмся в начальное полуребро. Помечать использованные.
5. **Фильтрация.** Для каждой грани посчитать знаковую площадь. Внешнюю грань (знак противоположен остальным / наибольшая по модулю) отбросить. Грани с площадью `< 0.5 м²` отбросить.
6. **Площадь комнаты** считать по **осевым линиям** стен (допущение: упрощение MVP, записать в UI «по осям стен»).

Тесты: прямоугольник → 1 комната; прямоугольник с перегородкой (T-стыки) → 2 комнаты; незамкнутый контур → 0 комнат; L-образная комната; пустой план → [].

## 8. Распознавание стен из растра (`src/raster`)

### 8.1 Предположения (записать в UI в подсказке)
Чертёж чёрно-белый или светлый фон с тёмными стенами; стены **толстые** (заливка или толстые линии), **ортогональные** (горизонтальные и вертикальные); тонкие линии (размеры, мебель, штриховка, текст) должны отфильтровываться. Диагональные стены в MVP не распознаются (пользователь дорисует вручную).

### 8.2 `prepareImage(file: File, maxSidePx = 1600)`
- Декодировать через `createImageBitmap`, нарисовать в canvas, **уменьшить так, чтобы большая сторона ≤ `maxSidePx`** (если больше).
- Вернуть `{ imageData: ImageData; blob: Blob /* уменьшенный PNG */; widthPx; heightPx }`.
- **Единое пиксельное пространство:** подложка в редакторе, калибровка и распознавание используют ТОЛЬКО это подготовленное изображение. Исходный размер дальше нигде не нужен.
- Лимит файла 15 МБ, форматы PNG/JPG/WEBP; иначе понятное сообщение об ошибке.

### 8.3 Калибровка
Инструмент `calibrate`: пользователь кликает 2 точки на подложке, вводит реальное расстояние (м, число > 0). `metersPerPixel = realMeters / distPx(p1,p2)`. Сохранить в `Underlay`. Пока масштаб не задан, кнопка «Распознать стены» неактивна. Точки калибровки показать на экране, их можно перетащить.

### 8.4 Сигнатура

```ts
export interface DetectOptions {
  metersPerPixel: number;
  threshold?: number | 'otsu';       // по умолчанию 'otsu'
  invert?: 'auto' | boolean;         // 'auto': если средняя яркость < 110 → фон тёмный → инвертировать
  thicknessPx?: number | 'auto';     // 'auto'
  minWallLengthM?: number;           // 0.4
  snapToleranceM?: number;           // 0.15
  doorGapRangeM?: [number, number];  // [0.6, 1.3]
  defaultHeight?: number;            // 2.7
}
export interface DetectResult {
  walls: Wall[];
  openings: Opening[];
  stats: { thicknessPx: number; thresholdUsed: number; wallsFound: number; ms: number };
}
export function detectWalls(
  img: { data: Uint8ClampedArray; width: number; height: number },
  opts: DetectOptions
): DetectResult;
```

Функция **чистая**, без DOM и canvas. Запускается из `detect.worker.ts` через `postMessage` (с `Transferable` для буфера); в UI показывать индикатор загрузки.

### 8.5 Алгоритм (все шаги реализовать вручную на типизированных массивах)

1. **Серый:** `g = 0.299 R + 0.587 G + 0.114 B` (прозрачные пиксели считать белыми).
2. **Порог:** метод Оцу (гистограмма 256 бинов). Маска «тёмное» `dark[i] = g[i] < T` (с учётом `invert`).
3. **Толщина стены `t` (px):** собрать длины горизонтальных и вертикальных серий тёмных пикселей, исключить серии ≤ 2 px и > `0.25·min(width,height)`; взять **моду** (самое частое значение в диапазоне `[3, maxT]`). Если данных мало — `t = 6`. Допускается переопределение через `thicknessPx`.
4. **Горизонтальная маска `H`:** в каждой строке пометить серии тёмных пикселей длиной `≥ Lmin`, где `Lmin = max(2.5·t, minWallLengthM / metersPerPixel)`. Остальное не помечать.
5. **Вертикальная маска `V`:** то же по столбцам.
6. **Связные компоненты** (4-связность, итеративный BFS/stack, без рекурсии) в `H` и `V` отдельно. Для каждой компоненты — bounding box.
   - В `H` оставить компоненты, где `высота bbox ∈ [0.5t, 2.0t]` и `ширина ≥ Lmin`. Стена: осевая линия `y = центр bbox`, `x ∈ [minX, maxX]`.
   - В `V` симметрично.
7. **Толщина стены (м):** `t_m = высота/ширина bbox × metersPerPixel`, округлить до 0.01; зажать в `[0.05, 0.6]`.
8. **Привязка (snap):** сначала сдвинуть вертикальные/горизонтальные осевые линии, отличающиеся меньше `snapTol` (px), к общему значению (кластеризация по 1D). Затем для каждого конца стены: если он в пределах `snapTol` от осевой линии другой (перпендикулярной) стены — продлить/укоротить конец до точки пересечения осей; если близок к концу другой стены — совместить.
9. **Слияние:** коллинеарные стены на одной оси с зазором `< snapTol` слить в одну.
10. **Двери из зазоров:** если между двумя коллинеарными стенами на одной оси зазор попадает в `doorGapRangeM` — **не сливать**, а слить стены в одну и создать `Opening { kind: 'door' }` по центру зазора с шириной = зазор. Зазоры вне диапазона не трогать (стены остаются раздельными).
11. **Пиксели → метры:** `x_m = x_px · metersPerPixel`. Присвоить `id`, `height = defaultHeight`.
12. Отбросить стены короче `minWallLengthM`.

### 8.6 Тесты `detectWalls` (синтетические изображения в памяти)
Генерировать изображение функцией `drawRect(buf, w, h, x, y, rw, rh, value)`:
- Прямоугольная комната (4 стены толщиной 8 px) → ровно 4 стены, концы совпадают (допуск 1 px × mpp).
- То же + тонкие линии толщиной 1–2 px и «шум» → всё равно 4 стены.
- Комната с перегородкой → 5 стен (T-стык).
- Стена с зазором ~0.9 м → 1 стена (слитая) + 1 дверь.
- Инвертированное изображение (светлые стены на тёмном) при `invert:'auto'` → тот же результат.
- Пустое белое изображение → 0 стен, без ошибок.
- Производительность: 1600×1200 обрабатывается < 1.5 с на обычном ноутбуке.

### 8.7 UX распознавания
1. Кнопка «Распознать стены» → воркер → результат кладётся в `uiStore.draft`.
2. Черновик рисуется поверх подложки **цветом-акцентом (оранжевый), пунктиром**, толщина как у настоящих стен.

## 9. 2D-редактор (`src/editor2d`)

### 9.1 Вьюпорт
SVG на весь контейнер. Преобразования: `screen = (world · zoom) + pan`. Колесо мыши — масштаб относительно курсора (диапазон 20…400 пикс/м, начальный 80); пан — среднее колесо, либо `Space` + drag, либо тачпад-жест. Всё через Pointer Events с `setPointerCapture`. Курсор по умолчанию в метрах показывается в строке состояния.

### 9.2 Слои (порядок снизу вверх)
Сетка (шаг `gridStep`, подпись каждые 1 м) → подложка (`<image>` с `opacity`) → комнаты (светлая заливка + подпись «Комната N · X.XX м²») → стены (полигон толщиной стены, серый) → проёмы (дверь: белый разрыв + дуга; окно: тонкая синяя полоса) → мебель (прямоугольник + подпись) → черновик распознавания → оверлей (подсказки привязки, ручки выделения, измерения).

### 9.3 Привязка (snapping), `snapping.ts`
Чистая функция `snap(point, ctx): { point: Vec2; kind: 'endpoint'|'wall'|'grid'|'none' }`. Приоритет:
1. Конец существующей стены в радиусе 12 экранных пикселей.
2. Проекция на стену в радиусе 10 px (для T-стыков).
3. Узел сетки, если `snapEnabled`.
Модификатор **Shift**: блокировка направления на 0/45/90° относительно предыдущей точки.

### 9.4 Инструменты и поведение

| Инструмент | Горячая клавиша | Поведение |
|---|---|---|
| Выбор | `V` | Клик — выделить; drag — переместить (стена целиком, конец стены за ручку, мебель, проём вдоль стены). Один шаг истории на drag. `Del` — удалить. |
| Стена | `W` | Клик — начало, следующие клики продолжают цепочку. `Enter`/двойной клик/`Esc` — завершить. Показывать резиновую линию и длину в метрах. Ввод числа с клавиатуры во время рисования + `Enter` задаёт длину в метрах. |
| Дверь | `D` | Навести на стену → превью проёма; клик ставит. Проём не выходит за стену и не пересекает другой проём. |
| Окно | `N` | То же для окна. |
| Мебель | `F` | Выбор типа в панели → клик ставит в точку; потом можно двигать/вращать (ручка поворота; `R` — поворот на 90°). |
| Измерение | `M` | Две точки → расстояние в метрах (не сохраняется в план). |
| Калибровка | — | См. §8.3. |

Общие: `Esc` отменяет текущее действие и возвращает в «Выбор»; `Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z` (и `Ctrl+Y`) — undo/redo; `G` — вкл/выкл привязку.

### 9.5 Инспектор (правая панель)
Для выделенного объекта — поля с числовым вводом (метры):
- Стена: длина (изменяет конец `b`), толщина, высота.
- Проём: тип, ширина, высота, высота подоконника, смещение.
- Мебель: тип, X, Y, поворот (°).
Если ничего не выделено — настройки плана (толщина и высота по умолчанию, шаг сетки) и подложка (прозрачность, видимость, кнопки «Калибровка», «Распознать стены», «Удалить подложку»).

## 10. Смета (`src/estimate/estimate.ts`)

Чистая функция `estimate(plan, rooms, prices): EstimateResult`:

- `floorArea` — сумма площадей комнат (по осям).
- `perimeter` — сумма длин всех стен.
- `wallAreaNet` = Σ(длина × высота) − Σ(ширина × высота проёма) по всем стенам, **одна сторона**.
- `paintArea = wallAreaNet × 2` (две стороны; допущение, показать в подсказке).
- `openingsCount` по типам; `furnitureCount` по типам.
- Стоимость = `floorArea × prices.floor + paintArea × prices.paint + wallAreaNet × prices.wallBuild`.

Цены (₽/м²) редактируются пользователем в панели; значения по умолчанию условные: пол 1500, покраска 400, возведение стен 3500. Подпись: «Ориентировочная оценка, не коммерческое предложение». Хранить цены в `localStorage`. Деньги форматировать через `Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB', maximumFractionDigits: 0 })`.

Тесты: комната 4×5 м, стены 2.7 м, дверь 0.9×2.1 и окно 1.2×1.2 → проверить числа вручную.

## 11. 3D-вид (`src/view3d`)

### 11.1 Сцена
`Canvas` (R3F) с `shadows`, фон светло-серый, `ambientLight` + одна `directionalLight` с тенями, `Grid` из drei на уровне пола, `OrbitControls` (демпфирование, ограничение `maxPolarAngle ≈ π/2 − 0.05`). Кнопка «Сверху» ставит камеру прямо над планом (ортографическая или перспективная сверху); «Центрировать» — подгоняет камеру под bbox плана. Потолок по умолчанию выключен.

### 11.2 Стены: `wallMesh.ts` (чистая функция)

```ts
export interface Box { cx: number; cy: number; cz: number; sx: number; sy: number; sz: number; rotY: number }
export function wallToBoxes(wall: Wall, openings: Opening[], extendStart: number, extendEnd: number): Box[];
```

Алгоритм:
1. `L = |b − a|`, `angle = atan2(dy, dx)`, единичный вектор `dir`.
2. `extendStart/End` — удлинение концов на `thickness/2`, если конец соединён с другой стеной (закрывает угол). Определяется в `Scene` по близости концов (≤ 0.05 м).
3. Отсортировать проёмы по `offset`; интервалы `[offset − w/2, offset + w/2]`, прижатые к `[0, L]`.
4. Между интервалами — **сплошные куски** на полную высоту. Над каждым проёмом — **перемычка** от `sillHeight + height` до `wall.height` (если > 0). Под окном — **подоконный блок** от 0 до `sillHeight` (если > 0).
5. Каждый кусок → `Box`: центр вдоль стены, `rotY = −angle`, размеры (`длина куска`, `высота`, `thickness`).
6. Один общий материал для всех стен (светлый), `castShadow` и `receiveShadow`.

Тесты: стена без проёмов → 1 бокс; с дверью посередине → 2 сплошных + 1 перемычка; с окном → 2 сплошных + перемычка + подоконник; проём у самого края → без нулевых боксов.

### 11.3 Пол
`findRooms` → для каждой комнаты `THREE.Shape` из полигона → `ShapeGeometry`, повернуть на `−π/2` вокруг X (учесть, что 2D `y` → 3D `z`; проверить визуально и тестом площади). Материал светло-бежевый.

### 11.4 Мебель
Для каждого `Furniture` — группа с `position (x, 0, y)`, `rotation.y = −rotation`, внутри боксы из каталога.

### 11.5 Производительность
Геометрию пересчитывать только при изменении `walls`/`openings` (`useMemo`). Никаких ререндеров 3D на `pointermove` 2D-редактора (подписка на нужные срезы store через селекторы).

### 11.6 Экспорт
`exportGlb.ts`: `GLTFExporter` из `three/examples/jsm/exporters/GLTFExporter.js`, `binary: true` → файл `.glb`; экспортировать группу с моделью без сетки/хелперов. PNG — снимок канваса (`gl.render` затем `toDataURL('image/png')`).
